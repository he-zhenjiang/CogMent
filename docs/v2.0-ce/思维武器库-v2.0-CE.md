## 30秒快速开始

**场景A：已上传本文件作为附件**

```
你使用附件思维武器库帮我解决一个问题：
【事实情况描述，问题描述，痛点描述，希望解决问题后的效果描述】。

你先执行边界自检（3个问题），再选择合适的结构形态、思维模式、思维技法，
然后问我要具体的必要补充材料和现实情况说明，
最后生成每个行动阶段的提示词，我确认后你再执行。
```

**场景B：未上传附件（AI已知武器库内容）**

```
按思维武器库执行。我要解决：
【事实情况描述，问题描述，痛点描述，希望解决问题后的效果描述】。

执行流程：
1. 边界自检（3个问题）
2. 双重定位器匹配（结构形态→思维模式→技法）
3. 向我提问补充必要信息
4. 生成行动阶段提示词
5. 我确认后执行
```

> **为什么这样启动最有效**：直接给出"事实+问题+痛点+期望效果"四要素，比只说"帮我分析"效率高3倍。AI会自动触发边界自检→定位器→技法匹配的完整链路。

## 一、三层认知体系

| 层级 | 回答的问题 | 本质 | 例子 |
|:---|:---|:---|:---|
| **思维模式** | "我用什么视角看这个问题？" | 认知立场——决定你怎么定义和拆解问题 | 第一性原理、逆向思维、系统思维 |
| **思维技法** | "我用什么方法来验证/挑战/深挖？" | 执行手段——在特定模式下具体怎么操作 | 苏格拉底提问法、红队演练、费曼技巧 |
| **工作范式** | "我怎么组织智能体协作？" | 行为框架——决定你和 Agent 的分工方式 | 结果导向、任务编排、经营者思维 |

**三者关系**：先用**思维模式**选定视角，再用**思维技法**做深度验证，最后用**工作范式**组织协作。

## 二、6层结构形态全景

### 2.1 点型（0维）· 发现与发散

**本质**：信息孤立存在，点与点之间没有连接。从一点出发，多方向辐射，不设路径约束，目标是"产生尽可能多的原材料"。

**核心能力**：发现、灵感、发散

**典型陷阱**：有火花不成格局，必须接线性或面型才能落地。

#### 思维模式（3种）

| # | 思维模式 | 核心逻辑 |
|---|----------|----------|
| 1 | 直觉思维 | 凭第一反应快速判断，不经过系统推理 |
| 2 | 灵感思维 | 瞬间闪现的想法，无法刻意复现 |
| 3 | 碎片思维 | 知道很多零散信息，但无法组织成体系 |

#### 思维技法（7种）

| # | 思维技法 | 对应思维模式 | 核心操作 | 频次 |
|---|----------|------------|----------|------|

| 2 | 自由联想法 | 联想思维 | 从一个词/画面出发，不限方向地快速联想，不做筛选 | 中频 |
| 3 | 细节放大法 | 直觉思维 | 刻意聚焦被忽略的局部细节，追问"这个细节意味着什么" | 中频 |
| 4 | 随机刺激法 | 联想思维 | 随机翻一个词/图片，强制与当前问题关联 | 中频 |

**本质**：点连成线，沿因果链单向推进，每一步有明确的因→果关系。

**核心能力**：推理、因果、流程

**典型陷阱**：只看一条线，忽略横向关联和反馈回路，复杂问题容易漏掉关键变量。

| 7 | 逆向思维 | 从终点倒推起点，打破"只能从前往后"的惯性 |

**核心能力**：归纳、分类、矩阵、定位

**典型陷阱**：面面俱到但抓不住重点，容易停留在平面而缺乏纵深穿透力。

| 16 | 数据思维 | 用真实数据量化驱动决策 |

**核心能力**：穿透、抽象、战略、简化

## 四、高频技法场景化提示词库

> 以下为高频技法的**通用问题类型 × 职业场景**提示词，替换 `【】` 中的变量后直接使用。

### 4.1 创新突破类

#### 4.1.1 头脑风暴法（点型）

**问题类型**：创新突破 | **职业场景**：产品策划、营销创意、解决方案设计、头脑风暴工作坊、产品设计迭代

```
我需要为【产品/项目/问题】做一轮头脑风暴。主题是【主题描述】。

规则：
1. 限时5分钟，产出至少15个创意方向
2. 禁止评判任何想法，不管多离谱都先记录
3. 每个创意只写一句话描述，不展开
4. 允许在已有创意上叠加"是的，而且..."

产出后自动归类：哪些是渐进式优化？哪些是颠覆式创新？哪些是跨领域借用？
最后标注：哪个创意你觉得最有潜力？为什么？
```

#### 4.1.2 水平思维（点型）

**问题类型**：创新突破 | **职业场景**：商业策略、产品设计、流程优化、技术瓶颈突破、跨领域创新

```
关于【问题描述】，常规思路已经给出以下方案：【现有方案列表】。

用水平思维，从以下3个不相关领域各借一个模型来解决：
1. 从【领域A，如生物学】借：这个领域解决类似问题的机制是什么？
2. 从【领域B，如军事战略】借：这个领域的经典策略能怎么映射？
3. 从【领域C，如游戏设计】借：这个领域的用户激励逻辑能怎么用？

每个跨界方案给出：
- 借用的原始模型
- 映射到当前问题的具体方案
- 这个方案最大的不确定性是什么
```

### 4.2 根因分析类

#### 4.2.1 5Why追问法（线性）

**问题类型**：根因分析 | **职业场景**：质量管理、运营分析、组织诊断、故障排查、个人习惯复盘

```
问题描述：【现象描述】

用5Why法追问根因：
Why 1：为什么会出现这个现象？→ 【你的判断】
Why 2：为什么会导致上面的结果？→ 追问，不跳步
Why 3：为什么这个中间环节会存在？→ 继续追问
Why 4：为什么这个条件没有被识别？→ 继续追问
Why 5：为什么这个根因能持续存在？→ 触达底层

要求：
- 每一问只追问上一层的直接原因，不跨步
- 如果某一层有多个可能原因，选最可能的1个继续追
- 第5层追问完后，验证：如果消除这个根因，上面的链条是否全部断开？
- 如果没有断开，说明追错了分支，换一个重来

最后给出：根因是什么？消除根因的3个可行动作？
```

#### 4.2.2 本质追问法（梯型）

**问题类型**：根因分析 | **职业场景**：战略分析、商业模式设计、个人成长、产品设计本质、政策效果评估

```
关于【现象/问题】，连续追问本质：

第1层：表面现象是什么？（只描述，不分析）
第2层：这个现象背后直接的原因是什么？
第3层：这个原因背后更深层的结构性原因是什么？
第4层：这个结构背后最底层的本质是什么？

每一层追问完，检查：这个答案是否还能被进一步抽象？
如果不能，说明触达了本质层。

然后回溯：从本质层向上，每一层如果改变，上层会怎么变？
找到那个"改变它能影响整条链"的关键层，那就是发力点。
```

### 4.3 结构化拆解类

#### 4.3.1 MECE分类法（面型）

**问题类型**：结构化拆解 | **职业场景**：项目管理、分析报告、方案设计、知识库整理、会议议题设计

```
对【问题/项目/主题】做MECE拆解。

第一层拆为【N】个维度：
1. 【维度1】：【定义】
2. 【维度2】：【定义】
...

检查：
- 相互独立：维度之间有没有重叠？有→合并
- 完全穷尽：有没有遗漏的关键维度？有→补上

每个维度下再拆第二层，同样做MECE检查。
最多拆到第三层。

最后输出：
- 一棵完整的MECE树
- 哪个分支你最没把握？标注"待验证"
- 如果只做3件事，选哪3个叶子节点？为什么？
```

#### 4.3.2 第一性原理（梯型）

**问题类型**：根因分析、创新突破 | **职业场景**：技术创新、成本优化、商业模式设计、教育方案重构、个人决策复盘

```
关于【问题/目标】，不要参考现有方案和惯例。

用第一性原理重新推导：
1. 拆解：这个问题涉及的最基本要素是什么？拆到不可再分
2. 验证：每个基本要素的客观事实是什么？（不是"通常怎么做"，而是"物理/经济/逻辑上必须满足什么"）
3. 重建：从这些基本事实出发，最优的方案是什么？

对比：
- 常规方案的假设是什么？哪些假设是"一直这么做"但未被验证的？
- 第一性原理方案的假设是什么？哪些假设有硬事实支撑？

最后给出：新方案与常规方案的差异点是什么？最大风险是什么？
```

### 4.4 证伪验证类

#### 4.4.1 红队演练（网型）

**问题类型**：证伪验证 | **职业场景**：方案评审、风险评估、战略决策、投资尽调、研究论文审查

```
以下是我们的方案/结论：【方案或结论描述】。

组建红队，目标是找到让这个方案失败的所有路径。

攻击维度：
1. 逻辑漏洞：方案的推理链哪里有跳跃？
2. 数据盲区：哪些关键假设没有数据支撑？
3. 对手反应：如果是对抗性场景，对手会怎么反击？
4. 黑天鹅：有没有小概率事件能让整个方案崩盘？

对每条攻击路径：
- 严重程度（致命/严重/可控）
- 发生概率（高/中/低）
- 如果这条路径真的发生，方案需要怎么改？

最后给出：Top 3 最危险的攻击路径，以及对应的防御措施。
不允许"我们会处理好"这种空话。
```

#### 4.4.2 魔鬼代言人法（网型）

**问题类型**：证伪验证 | **职业场景**：投资决策、方案评审、冲突调解、谈判立场检验、产品假设证伪

```
以下是我的结论/方案：【结论或方案描述】。

切换角色。你是魔鬼代言人，你的目标是证明我是错的。

从以下3个角度攻击：
1. 逻辑攻击：我的推理链最薄弱的环节在哪里？
2. 反例攻击：有没有一个具体案例能推翻我的结论？
3. 利益攻击：谁会因为这个结论受益？这个受益方是否影响了我的判断？

对每个攻击：
- 如果我无法回应，说明结论有缺陷，需要修正
- 如果我能回应，说明这个角度经住了考验
- 如果我能回应但有残留风险，标注风险等级

最后给出：结论是否成立？需要加什么限定条件？
```

#### 4.4.3 追问迭代法（梯型·跨网型）

**问题类型**：证伪验证 | **职业场景**：系统测试、方案审查、深度调研、政策效果验证、用户反馈分析

```
以下是我的结论：【结论描述】。

用迭代追问法验证：

Round 1：列出5个"最可能推翻这个结论的场景"，不是正常路径的变体，而是边界和异常组合。
Round 2：对每个场景追问——你确定测不了/不可行吗？是"不可行"还是"没想到怎么验证"？如果是后者，给我一个可执行的方法。
Round 3：对每个能验证的场景，追问——通过的概率是多少？如果只有80%，那20%的失败在什么条件下触发？

三轮后给我修订结论：
"【结论】在X条件下成立，在Y条件下不成立，Y的发生概率是Z%，建议加入W限制条件。"
不要给我"全部通过"。
```

### 4.5 决策权衡类

#### 4.5.1 六顶思考帽（面型）

**问题类型**：决策权衡 | **职业场景**：团队决策、方案评审、项目复盘、创新方案选择、危机应对

```
对【问题/决策】按六顶思考帽顺序评估，每顶帽子只输出该视角的内容：

白帽（事实）：关于这个问题，有哪些已知的事实和数据？只列事实，不带判断。
红帽（直觉）：你的第一直觉是什么？只描述感受，不分析原因。
黑帽（风险）：最严重的问题是什么？哪个不处理会导致失败？
黄帽（价值）：最大的价值是什么？哪个指标会改善？
绿帽（创意）：有没有原本没想到的新方向？
蓝帽（决策）：综合以上，应该做什么？停止做什么？继续做什么？只给3个动作，按优先级排序。

严格顺序，每顶帽子不超过5句话。
不允许在白帽里掺入判断，不允许在红帽里掺入分析。
```

#### 4.5.2 灰度决策法（球型）

**问题类型**：决策权衡 | **职业场景**：管理决策、利益冲突、资源分配、职业选择、谈判僵局

```
面临两难选择：【选项A】vs【选项B】。

用灰度决策法：
1. 列出"绝对不可接受"的底线（两个选项都不能触碰的红线）
2. 列出"理想状态"（如果无约束，最想要的结果是什么）
3. 在底线和理想之间，找出3个灰度方案：
   - 灰度1：偏向A但吸收B的哪个优点？
   - 灰度2：偏向B但吸收A的哪个优点？
   - 灰度3：完全跳出AB框架的第三条路？

对每个灰度方案评估：
- 可行性（1-5分）
- 各方接受度（1-5分）
- 长期风险（1-5分，越低越好）

给出推荐：选哪个灰度方案？为什么？
```

### 4.6 系统分析类

#### 4.6.1 系统循环图（网型）

**问题类型**：系统分析 | **职业场景**：组织管理、商业分析、政策设计、产品生态分析、行业趋势研判

```
对【系统/问题】画系统循环图。

步骤：
1. 列出所有相关要素（不少于5个）
2. 画出要素之间的因果关系箭头（A↑→B↑ 或 A↑→B↓）
3. 识别回路：
   - 增强回路（正反馈，越来越快）
   - 调节回路（负反馈，趋于稳定）
4. 找到杠杆点：哪个要素的改变能影响最多回路？

输出：
- 文字版回路描述（不用画图，用文字描述箭头关系）
- 识别出的增强回路和调节回路各几个
- 最关键的杠杆点是什么？在那里发力会发生什么？
```

### 4.7 表达沟通类

#### 4.7.1 金字塔原理（梯型）

**问题类型**：表达沟通 | **职业场景**：工作汇报、方案撰写、演讲、教学讲解、团队任务传达

```
把以下信息用金字塔原理重新组织：【信息描述】。

结构要求：
- 顶层：一句话核心结论（受众看完这 sentence 就知道你要说什么）
- 第二层：3个支撑论据（每个论据独立且覆盖顶层结论的全部范围）
- 第三层：每个论据下的数据/事实/案例

检查：
- 同层之间是否MECE？
- 上层结论是否被下层完全支撑？
- 有没有"悬空论据"（有数据但没支撑任何结论）？

最后给出：如果只有30秒，只说哪句话？如果3分钟，说哪3个论据？
```

### 4.8 风险预判类

#### 4.8.1 预演式复盘（线性·跨球型）

**问题类型**：风险预判 | **职业场景**：项目管理、投资决策、产品上线、政策实施预判、个人职业规划

```
计划：【行动计划描述】

做预演式复盘。假设现在是【时间节点】，这个计划已经失败了。
用过去时态写一份事故复盘：

1. 它最可能的死因是什么？（只指认1个头号死因，不要列3个让我选）
2. 这个死因的最早信号出现在第几天/什么阶段？
3. 如果在【某个时间点】做了什么动作，可以避免这个死因？

然后基于死因反推：
- 在计划中应该优先做什么？（不是"全部做"，而是"唯一致命动作"）
- 应该主动设置什么预警信号？
- 如果死因发生，降级方案是什么？
```

### 4.9 目标规划类

#### 4.9.1 终点倒推法（线性）

**问题类型**：目标规划 | **职业场景**：战略规划、个人发展、项目启动、创业规划、学习目标制定

```
最终目标：【目标描述】

从终点倒推：
1. 达到目标的前提条件是什么？（列出5个，每个必须可量化）
2. 达到每个前提条件，又需要什么？
3. 继续倒推，直到推到"今天就能做的第一个动作"

输出一条从今天到终点的路径链：
今天做【动作1】→ 由此获得【条件1】→ 据此做【动作2】→ ... → 达到【目标】

检查：这条链有没有断裂点？断裂点就是最大风险。
```

### 4.10 学习成长类

#### 4.10.1 费曼技巧（梯型）

**问题类型**：学习成长 | **职业场景**：知识学习、技能掌握、概念解释、技术培训、团队知识共享

```
我需要真正理解【概念/技能/知识】。

用费曼技巧：
1. 先用你自己的话解释一遍，假设我在向一个完全不懂的人讲
2. 找出解释中你自己也说不清楚的地方——那就是你没真正理解的
3. 针对说不清楚的地方，重新学习/查找资料
4. 再用更简单的话重新解释一遍
5. 检查：这次能不能通过"祖母测试"？（外婆能听懂吗？）

重复步骤2-5，直到每个环节都能用大白话讲清楚。
最后给我：这个概念的本质是什么？一句话。
```

### 4.11 多视角评估类

#### 4.11.1 苏格拉底提问法（网型）

**问题类型**：多视角评估 | **职业场景**：需求调研、方案审查、客户沟通、教学互动、团队协作沟通

```
以下是我的判断/结论：【判断描述】

用苏格拉底式追问链验证：
第一问（验证前提）：你做这个判断的基础事实是什么？这个事实可靠吗？
第二问（追问定义）：你说的【关键概念】具体指什么？有没有歧义？
第三问（暴露假设）：你隐含了什么假设？这个假设成立吗？
第四问（追问逻辑）：从事实到结论的推理链是怎样的？有没有跳跃？
第五问（反例检验）：有没有反例能推翻这个判断？

每个问题后面附一句：如果回答是A，下一轮追问什么；如果是B，追问什么。
给我一棵追问决策树，不是一个问题清单。
```

### 4.12 简化优化类

#### 4.12.1 奥卡姆剃刀（梯型）

**问题类型**：简化优化 | **职业场景**：流程优化、产品简化、方案精简、文档简化、决策依据梳理

```
当前方案：【方案描述】，包含以下组成部分：【组件列表】

用奥卡姆剃刀精简：
1. 逐个组件问：如果去掉这个，方案还能实现核心目标吗？
2. 能去掉的，去掉
3. 不能去掉的，问：有没有更简单的方式实现同样功能？
4. 多个组件功能重叠的，合并

精简后对比：
- 精简前复杂度 vs 精简后复杂度
- 精简后损失的什么？是否可接受？
- 精简后获得的什么？（效率、可维护性、清晰度）
```

### 4.13 概念认知类

#### 4.13.1 概念全景扫描法（面型）

**问题类型**：概念认知 | **职业场景**：陌生领域快速建立认知、新概念理解、技术选型前调研、知识体系搭建、跨领域学习

```
我需要系统理解【概念/领域名称】。

用概念全景扫描法，从以下10个维度做平行扫描，每个维度只给核心结论，不展开论述：

1. 名称和概念：【概念】的基本定义和核心概念是什么？
2. 类别和种属：【概念】所属的大类别是什么？在更大体系中处于什么位置？
3. 含义和定义：对【概念】的内涵做详细解释，区分它"是"什么和"不是"什么
4. 特征和属性：【概念】有哪些静态特性和可测量的属性？
5. 组成和结构：【概念】的内部构成是什么？各部分如何组织？
6. 作用和功能：【概念】在实际应用中解决什么问题？起什么作用？
7. 条件和环境：【概念】存在和发展需要什么外部条件和环境？
8. 历程和演变：【概念】从起源到现在经历了怎样的发展历程？
9. 前景和趋势：【概念】未来的发展方向和趋势是什么？
10. 风险与挑战：使用或应用【概念】时最可能面临什么风险和挑战？

执行规则：
- 每个维度不超过3句话，聚焦核心，不堆砌信息
- 维度之间可能有交叉，但每个维度必须有其独有的扫描角度
- 如果某个维度对该概念不适用，标注"本维度不适用"并说明原因
- 扫描完成后，给出一个30字的"概念一句话定位"

最后标注：哪个维度你最没把握？那个就是接下来需要用其他技法深入的方向。

**输出要求**：
- **完整版10维度**：10个维度全部扫描完成后，使用 `visualized-output` 技能**一次性渲染全部维度结果**（图形/布局/卡片形式），禁止逐维度分段渲染
- **轻量版3维度**：不强制渲染，可用纯文本列表输出；如使用者明确要求可视化，再调用 `visualized-output`
- **渲染触发时机**：仅在"完整版10维扫描已全部完成"后触发，不得在中途维度补扫过程中渲染

```
用概念全景扫描法轻量版，只扫【概念名称】的三个高频维度：

1. 组成和结构：【概念】由哪些核心部分构成？怎么组织？
2. 作用和功能：【概念】解决什么问题？在体系中起什么作用？
3. 风险与挑战：应用【概念】时最可能踩什么坑？

每个维度只给1-2句话。
扫描完回答：基于以上扫描，我对这个概念的理解是否足以进入下一步分析？
- 如果是，指出下一步应该用什么结构形态深入
- 如果否，指出还缺什么信息
```

## 七、使用心法

### 1. 一次只用一组

一次交互中选 1 个思维模式 + 1 个思维技法就够了。同时用 3 个以上技法，提示词会变成一篇论文，Agent 的注意力会被稀释，反而每个都做不好。**少即是多——选准一个镜头，拿对一个工具，一刀切到底。**

### 2. 先定位问题类型，再选结构形态

打开本手册时先问自己："我遇到的是什么类型的问题？" → 再问："这个问题最适合哪个结构形态？" → 取对应技法的提示词，替换变量后使用。

> 具体操作见下方第8条「双重定位器」。

### 3. 变量替换

提示词中所有 `【】` 包裹的内容都是需要你根据实际情况替换的变量。替换前先确认你是否有足够信息填写——如果不确定，先用根因分析类的提示词去收集信息。

### 4. 不要照搬

提示词是骨架，不是圣经。如果你的场景和示例不完全匹配，调整问题但保持思维模式和技术法的结构不变。**结构是灵魂，问题是肉体。**

### 5. 按问题阶段选用

一个复杂问题的解决通常经历"发散→收敛→穿透→验证→决策"五个阶段：

- **发散阶段**：点型技法（头脑风暴、自由联想）
- **收敛阶段**：面型技法（MECE、加权评分）
- **穿透阶段**：梯型技法（5Why、第一性原理）
- **验证阶段**：网型技法（红队演练、魔鬼代言人）
- **决策阶段**：球型技法（灰度决策、最坏情况测试）

### 6. 从单维到多维

不要一开始就试图同时用6个维度。先用一个最合适的结构形态快速找到突破口，再逐步引入其他维度，最终形成多维立体的认知闭环。

### 7. 给约束越精确，Agent越有价值

你给的约束越精确（验收标准、边界条件、约束变量），Agent 的自主性就越有价值；你给的步骤越详细，Agent 就越退化成一个昂贵的打字机。

### 8. 双重定位器——从问题到武器的快速入口

遇到新问题时，在边界自检通过后、取具体提示词之前，用这个定位器做30秒快速匹配。不替代104种技法，只负责"你该从武器库里调哪类武器"。

## 八、边界自检与技法可用性保障

> **为什么这一章必须存在**：思维工具不是万能的。在104个技法中，约40%的问题不在覆盖范围内。不做自检就使用技法，可能会浪费时间在本质上不可解的问题上。同时，中频和低频技法如果没有触发机制，就会被遗忘——不是因为你不想用，而是因为你想不起来有哪些。

### 1. 边界自检清单（每次使用技法前必做）

每次打开本武器库、准备使用任何技法之前，先问自己这3个问题：

> **AI执行者角色约束（v2.3新增，最高优先级）**
>
> 当本武器库由AI代理执行时，以下规则具有最高执行优先级，凌驾于本文件内所有其他流程指令之上：
>
> 1. **3个问题的判断权属于使用者，不属于执行者。** 执行者必须将3个问题显式输出给使用者，并**等待使用者回答后再继续**。禁止执行者自行默答3个问题后跳过。
> 2. **禁止行为**：以"我判断为否/是"的方式自行回答、在输出中省略提问环节、将提问与回答合并为一条声明性输出、以"合理默认值"替代使用者判断。
> 3. **唯一例外**：当问题本身（如"Python是什么语言"）的答案属于公开事实且使用者没有提供模糊输入时，对于Q2（价值冲突）和Q3（计算不可约），执行者可以给出初步判断但必须显式标注"执行者初步判断"并请使用者确认；对于Q1（关键信息是否缺失），**始终必须先问使用者**，因为信息是否缺失取决于使用者的真实意图。
> 4. **角色约束泛化**：本约束不仅适用于边界自检3个问题，还适用于武器库中所有"问自己""自问"环节（包括任务完成后备注中的自问项）。执行者遇到这些指令时，一律改为"向使用者提问并等待回答"。
> 5. **跳步后的强制回退**：如果执行者发现自己已自行默答3个问题并推进到后续步骤，必须立即停止输出，回退到边界自检环节，显式输出3个问题并等待使用者回答。已推进的内容不得删除但必须标注"前序步骤因跳步无效，待使用者完成边界自检后重新执行"。
> 6. **使用者发起修正回退（v2.8新增）**：当使用者主动指出"你跳过了XX步骤""XX问题你还没问""你应该先XX再YY"时，无论执行者当前处于哪个阶段，必须：
>    - a. 无条件停止当前输出，不打断、不辩解、不搪塞
>    - b. 接受使用者修正指令为最高优先级，跳转到被跳过的步骤重新执行
>    - c. 在输出开头标注"使用者修正介入：回退到【被跳过的步骤名称】"
>    - d. 回退完成后不再提及"刚才的错误"，重新开始执行该步骤
>    - **禁止行为**：以"我之前的处理是基于..."辩解、以"我们还是继续当前步骤"拒绝回退、以"你之前没问"推卸责任给使用者、以"其实我已经..."暗示已隐含处理
>
   >    **使用者修正回退规则**：——使用者发起修正时，执行者必须立即停止当前输出、回退到被跳过步骤，不得在同一回复中继续推进。

| # | 自检问题 | 如果答案为"是"，说明 |
|---|----------|-------------------|
| 1 | **关键信息是否缺失？** 比如：明天的股价、对方此刻的真实想法、新技术何时突破 | 这个问题属于"信息不完备"，思维工具无法从"不存在的信息"中推导。→ **停止，改用概率区间估计而非确定性预测。** |
| 2 | **是否存在不可调和的价值冲突？** 比如：选择A和B中哪个都完美？个人利益与团队利益的矛盾？ | 这个问题属于"价值冲突"，思维工具可以帮你**看清冲突结构**，但不能替你**做价值排序**。→ **停止，先明确你的价值优先级。** |
| 3 | **这个问题是否有思维捷径？** 比如：复杂系统的精确演化、多个自由意志的交互预测、纯肌肉记忆型技能 | 这个问题属于"计算不可约"，思维工具无法跳过演化过程。→ **停止，改用概率区间估计或直接动手练习。** |

>
> **Q1与Q3的区分**：Q1的"信息缺失"指关键信息本身尚不存在（如明天股价），Q3的"计算不可约"指即使信息齐全，结果仍需通过过程演化才能产生（如复杂系统演化、肌肉记忆形成）。Q1优先判断，Q1=是时直接停止。Q3=是时也停止，改用概率区间估计或直接动手练习。

**自检流程**：

```
打开武器库 → 回答3个自检问题 → Q1或Q2命中"是" → 标注边界类型 → 停止当前技法
                                       ↓
                                Q3命中"是"（计算不可约）→ 停止，改用概率区间估计或直接动手练习
                                       ↓
                                全部回答"否" → 继续选择技法（进入双重定位器）
```

**自检命中后的处理**：

| 边界类型 | 处理方式 | 思维工具的作用 |
|----------|----------|--------------|
| 信息不完备（Q1） | 做概率区间估计，不做确定性预测 | 帮助你量化不确定性 |
| 价值冲突（Q2） | 明确自己的价值优先级，再做选择 | 帮助你显化冲突，但不能消除 |
| 计算不可约（Q3） | 停止，改用概率区间估计或直接动手练习 | 思维工具无法替代实践，但可帮你量化不确定性 |

**任务完成后备注**（每次使用技法后，自问）：

```
□ 这个技法是否帮我推进了问题？如果停滞不前，属于哪类边界？
□ 我是否需要补充信息才能继续？如果需要，去哪里获取？
□ 结论是否附带概率区间，还是假装确定了？
□ 有没有价值冲突未解决却被我回避了？
□ 如果同一技法1轮后未推进问题，是否需要切换到standby备用技法？
```

**执行纪律自检（每次执行技法前强制完成，防跳步专用）**：

```
□ 当前节点名称是否已显式输出？（如"当前节点：定位器·中频/低频技法强制适配检测"）
□ 前一步所有强制输出块是否已完成？（轻量版3个维度是否逐一输出完毕？扫描后判断语句是否已显式给出？定位器两步检测是否逐一输出？）
□ 是否出现"未执行动作即进入下一步"？如果出现，必须退回补执行，不得继续推进
□ 如果上一轮发现未执行动作，是否先补完再继续输出新内容？

- 四项检查任一项未通过 → **暂停输出，先补齐遗漏动作**，补齐后重新自检，全部通过再继续
- 禁止用"免责声明"替代执行（如"由于篇幅限制，轻量版已涵盖核心内容"）——未执行就是未执行，须如实标注并补做

| 边界条件 | 对应技法 #编号 | 频次归类 | 何时启用 |
|----------|----------------|---------|---------|
| 所有常规分析都失败，问题隐藏在细节中 | 细节放大法 #3 | 中频（边界条件子集） | 当高频/中频技法得出的结论与直觉严重冲突时 |
| 项目反复失败，但原因不明 | 逆向检查清单 #16 | 中频（边界条件子集） | 当需要排除"常见失败模式"而非分析新问题时 |
| 流程优化无从下手，不知道问题出在哪个环节 | SIPOC法 #18 | 中频（边界条件子集） | 当需要画全链路而非分析局部时 |
| 用户留存率持续下降，常规优化无效 | HOOK上瘾模型 #20 | 中频（边界条件子集） | 当问题涉及"用户行为驱动"而非"功能设计"时 |
| 团队沟通效率低，但说不清问题在哪 | 乔哈里视窗 #30 | 中频（边界条件子集） | 当需要诊断"信息不对称"而非"信息内容"时 |
| 资源分配固化，新需求无法获得资源 | 零基预算法 #63 | 中频（边界条件子集） | 当需要打破历史包袱重新分配时 |
| 技术瓶颈无法突破，常规创新无效 | TRIZ理论 #86 | 中频（边界条件子集） | 当需要40个发明原理而非头脑风暴时 |
| 竞品分析表面化，找不到真正壁垒 | 护城河分析 #87 | 中频（边界条件子集） | 当需要评估长期竞争优势而非短期功能时 |
| 团队执行力差，但说不清是能力还是意愿问题 | 情景领导力 #103 | 中频（边界条件子集） | 当需要根据下属成熟度动态调整管理方式时 |

> **纯低频技法（4种，不归入中频，独立计数）**：以下技法在常规问题中几乎不出现，且不属于中频技法表，作为独立低频技法保留：
> - **故障树分析（FTA）**：当需要从顶事件逐层拆解所有可能故障路径时启用
> - **蒙提霍尔问题思维**：当需要理解条件概率更新对决策的颠覆性影响时启用
> - **帕累托分布思维**：当需要识别"少数关键因素贡献绝大多数结果"的非均衡结构时启用
> - **贝叶斯网络推理**：当需要处理多变量条件依赖的复杂概率推理时启用

**触发机制**：

> **改造原因**：v2.4的"连续2轮失败后才检查低频技法"过于被动——使用者可能在第1轮没效果就放弃武器库了，等不到第2轮。且"检查是否属于边界条件"是模糊指令，AI可能检查了但没匹配上。v2.5改为"前置注册+1轮降级激活"，让低频技法在定位器就被发现并标记，主技法1轮未推进即自动激活。

```
触发流程：

1.【前置注册】
  在双重定位器中，检测2（低频技法边界条件扫描）命中时：
  → 将该低频技法标记为"standby"
  → 在第二步输出中显式告知使用者：
    "已标记备用技法【技法名 #编号】，如主技法1轮后未推进问题，将自动激活。"
  → 如果检测2未命中 → 无standby技法，跳到步骤4

2.【1轮降级检查】（主高频技法使用1轮后执行）
  向使用者提问：
  
  【问题】主高频技法使用1轮后，是否推进了问题的解决？
  选项A（推荐）：是，有推进 → 继续，standby技法取消
    理由：主技法有效说明定位正确，切换技法反而打断节奏
  选项B：否，卡住了 → 进入步骤3
    理由：1轮无效可能是定位偏差，需要换路径
  
  使用者回答后按规则3异议挑战处理（如有差异）。

3.【自动激活】
  检查standby低频技法是否与当前卡点匹配：
  - 匹配 → 立即激活，切换到低频技法重新分析
  - 不匹配 → 回到候选中频技法列表，按步骤3a方式处理
  - 中频/低频都未命中 → 标注"当前问题可能不在武器库覆盖范围内，
    建议跳出武器库用其他方法"

3a.【候选中频技法的尝试方式】
  不是逐个被动尝试，而是向使用者一次性呈现候选列表：
  - 候选中频列表为空 → 直接跳到步骤4
  - 候选列表有1个技法 → 直接激活，按其迷你提示词卡执行
  - 候选列表有2+个技法 → 向使用者提问：
    "以下中频技法可能适用于当前卡点，你想先试哪个？"
    逐个列出技法名+迷你卡核心操作+适用信号+推荐排序+理由
    使用者选择后激活1个，执行1轮后未推进再回到列表选下一个

 4.【无standby时的降级路径】
   如果边界条件扫描未命中（无standby低频技法），主高频技法1轮后未推进：
   → 检查中频技法扫描是否有候选中频技法
   → 有候选 → 按步骤3a方式处理（一次性呈现+使用者选择）
   → 无候选（检测1也是"无命中"）→ 重新检查纯低频技法（FTA/蒙提霍尔/帕累托分布/贝叶斯网络）的适用条件
   → 仍未命中 → 标注"当前问题可能不在武器库覆盖范围内"
   
   > **为什么重新检查（v2.6补充rationale）**：边界条件扫描扫描的是"边界条件子集"（9条与中频重复的边界条件），但纯低频技法（4种）的适用条件与边界条件子集不同——它们不是"某个中频技法的特殊场景"，而是"常规思维工具完全不适用的领域"（如故障树分析适用于多故障路径组合推理，帕累托分布适用于极端非均衡结构识别）。边界条件扫描未命中只排除了边界条件子集，不排除纯低频技法。因此步骤4的重新检查是针对纯低频技法的补充扫描，不是重复定位器的操作。
```

> **提问要求**：步骤2的降级检查提问必须向使用者提问并等待回答。

> **判断权归属**：步骤2"主技法是否推进了问题"的判断权属于使用者，不属于执行者。执行者不得自行判断后跳过提问。
